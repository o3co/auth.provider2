# session-store

Wires `session-lifecycle`'s store interfaces: session records to `subject-records`' records (`online-indexed`, erased by `session-lifecycle`), and the list of closings to deferred work. Each has its own space, and every space, the listings too, declares `confirmed-reads`, so the store answers its reads only from writes a failover keeps: an entry decides on a close another request wrote, and a revocation reads each subject's sessions to close them. The list of closings is spread over `closing-shards` shards (1–65536, default 1024) of up to `closings-per-shard` sessions (1–10000, default 1000); a session stays listed only while a participant keeps failing to close, so the defaults, about a million, leave room for a long outage while one shard stays near 50 KB. Each subject's listed sessions are `subject-records`' keyed sets, keyed by the subject (`online-keyed`, erased by `session-lifecycle`), on `kernel`'s clock, of up to the sessions `session-lifecycle` gives (`sessionsPerSubject`, its section's `sessions-per-subject`); a login rewrites its subject's set whole. Over the cap, the set pushes out the session ending first and keeps it awaiting, with its end, until `session-lifecycle` settles it (`awaiting`, `settled`, straight from the builder); `session-lifecycle` logs it and closes it, listing the closing first so a crash still finishes it. A need with nothing mapped to it, a guarantee, fails the type check, and `session-lifecycle`'s store contract, run on a store that loses what a missing guarantee allows, checks what each guarantee means. The wiring only maps, with no branches or loops. Both subject spaces sit at the tombstone's floor, beside their index spaces, over the phase the process reads once; the probe `session-store.phase` keeps the process out of traffic until it reads, and their erase and migrate ports come straight from the builders. The closings' space holds no subject's data (`subjectData: none`): handles awaiting their close. Depends on `kernel`, `session-lifecycle`, `records`, `subject-records` and `store`.
