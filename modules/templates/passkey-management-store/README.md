# passkey-management-store

Wires `passkey-management`'s store: its part of each subject's flow (`keyChangePart`: a key change's preimage, kept for a resend, or an expired op's mark) is bound to the space `passkey-management-store.flows` through `transparency-frames`' `frameParts`, so the frame store writes it in a flow's one write. The space is `retained`, following the log, and declares a guarantee for each need `passkey-management` states for its part (`keyChangePartNeeds`: never evicted, durable, replicated, confirmed reads, authenticated); a need with nothing mapped to it fails the type check. On a store that does not tell a write made outside the provider apart, it boots only under store's `accept-unauthenticated`. The wiring only maps, with no branches or loops. Depends on `kernel`, `passkey-management`, `store` and `transparency-frames`.
