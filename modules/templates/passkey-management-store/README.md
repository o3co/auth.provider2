# passkey-management-store

Wires `passkey-management`'s stores: `records`' records in two spaces, by the keys and for the lifetimes `passkey-management` gives, opaque here. `passkey-management-store.nonces` holds its nonces, with no subject's data (`subjectData: none`). `passkey-management-store.tokens` holds its mail tokens and its mail's side's answers; each names a subject and lives minutes, so it is `retained` and needs no subject writer, as nothing in it is found by subject. Each space declares a guarantee for each need either store states (never evicted, durable, replicated, confirmed reads, authenticated); a need of either with nothing mapped to it fails the type check. Its part of each subject's flow (`keyChangePart`: a key change's preimage, kept for a resend, or an expired op's mark) is bound to `passkey-management-store.flows` through `transparency-frames`' `frameParts`, so the frame store writes it in a flow's one write; it is `retained`, following the log, and declares a guarantee for each need `transparency` states for its frames. On a store that does not tell a write made outside the provider apart, all three boot only under store's `accept-unauthenticated`. The wiring only maps, with no branches or loops. Depends on `kernel`, `passkey-management`, `records`, `store`, `transparency` and `transparency-frames`.
