# approvals-store

Wires `approvals`' stores. Its statements' records are `records`' records in `approvals-store.statements`, each for the lifetime `approvals` gives; its part of each subject's flow (`approvalPart`: the state's approvals and use-once marks) is bound to `approvals-store.flows` through `transparency-frames`' `frameParts`, so the frame store writes it in a flow's one write. Both spaces are `retained`: a used statement holds the subject and credential its assertion showed, as the approval's record on the subject's flow keeps them, and the flow's part follows the log; neither needs a subject writer, as a Step's one write carries none. The statements' space declares a guarantee for each need `approvals` states, and the flows' space one for each need `transparency` states for its frames (never evicted, durable, replicated, confirmed reads, authenticated), which the frame store refuses any part's space to lack; a need with nothing mapped to it fails the type check. On a store that does not tell a write made outside the provider apart, both boot only under store's `accept-unauthenticated`. The wiring only maps, with no branches or loops. Depends on `kernel`, `approvals`, `records`, `store`, `transparency` and `transparency-frames`.
