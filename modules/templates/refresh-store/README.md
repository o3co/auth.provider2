# refresh-store

Wires `refresh`'s store interface. Its records (families, the key each is bound to, each code's link or mark) go to `subject-records` over the phase this process reads once, in `refresh-store.families`: `online-indexed`, each record created for its subject, fenced at creation by the subject's tombstone, erased by `refresh`, beside its index space, declaring `tombstoneFloor`, every port the builder's own (`create`, `read`, `change`, `erase`, `migrate`; never a raw `save` on an indexed space). `refresh`'s part of each subject's flow (`familiesPart`, the state's families) is bound to `refresh-store.flows`, `retained`, declaring each need the frames state, written by the flow's one write. The composition is out of traffic while the phase cannot be read (probe `refresh-store.phase`). The space declares a guarantee for each need `refresh` states (never evicted, durable, replicated, confirmed reads, authenticated); on a store that does not tell a write made outside the provider apart, it boots only under store's `accept-unauthenticated`. A need with nothing mapped to it fails the type check. The wiring only maps, with no branches or loops. Depends on `kernel`, `refresh`, `subject-records`, `store`, `transparency` (the frames' needs) and `transparency-frames` (`frameParts`).
