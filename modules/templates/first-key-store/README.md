# first-key-store

Wires `first-key`'s stores: `records`' records in two spaces, by the keys and for the lifetimes `first-key` gives, opaque here. `first-key-store.nonces` holds its nonces, with no subject's data (`subjectData: none`). `first-key-store.tokens` holds its mail tokens and its mail's side's answers; each names a subject and lives minutes, so it is `retained` and needs no subject writer, as nothing in it is found by subject. Each space declares a guarantee for each need either store states (`firstKeyNoncesNeeds`, `firstKeyTokensNeeds`: never evicted, durable, replicated, confirmed reads, authenticated); a need of either with nothing mapped to it fails the type check. On a store that does not tell a write made outside the provider apart, both boot only under store's `accept-unauthenticated`. The wiring only maps, with no branches or loops. Depends on `kernel`, `first-key`, `records` and `store`.
